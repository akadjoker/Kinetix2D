# Kinetix2D — Plan

2D physics engine on top of a minimal 2D engine (SDL2 + OpenGL ES 3.2 + glad + GLM).
Physics architecture follows proven references — no invented algorithms.

## Portability target: desktop + web + mobile

- GL API: stick to the GLES 3.0 subset (= WebGL2). No GLES 3.1/3.2-only features. Shaders are `#version 300 es`.
- Desktop runs the same GLES 3.0 context via Mesa/ANGLE; web builds with Emscripten (SDL2 + WebGL2 supported out of the box: `emcmake cmake`, `-sMIN_WEBGL_VERSION=2 -sMAX_WEBGL_VERSION=2 -sUSE_SDL=2`); mobile is native GLES.
- No platform ifdef soup: Window.cpp is the only file allowed to know the platform.
- 16-bit indices, stream VBO re-uploaded per frame — safe everywhere including WebGL2.

## Hard rules

- C++14 max.
- Containers: `ct` library only (`/media/projectos/projects/cpp/containers/include`) — `ct::Vector`, `ct::String`, `ct::HashMap`, `ct::Pool`, `ct::Arena`. No std containers, no `<vector>`/`<string>`/`<memory>`/`<algorithm>`. C headers are fine.
- Zero comments in code. If a decision truly needs explaining, one short English comment.
- No smart pointers. Raw pointers + clear ownership.
- No linked lists — arrays/handles/pools (`ct::Vector` + generational ids).
- Allman braces (user's editor enforces it).
- Math: SINGLE SOURCE OF TRUTH for 2D transforms = `k2d::Matrix2D` (affine a,b,c,d,tx,ty, user's render.cpp style) — GameObject local/global, sprite drawing (`Batch::DrawTexture(matrix)`, 4 corners inline), AND the kx physics transforms in M2+. `glm::vec2` for points/vectors. `glm::mat4` ONLY at the GL boundary (projection uniform, batch matrix stack for immediate/debug mode) via `Matrix2D::ToMat4()`. Never a second transform representation in gameplay or physics code. Rendering: BatchRenderer (ported from user's Aurora engine, inline GLES shaders).
- Every physics step validated against reference behavior; debug draw from day one.
- Build only what gets used: no speculative features, no unused abstractions. A seam is only allowed when its consumer is already named and scheduled. Delete code with no caller.

## References (do not invent)

- `/media/projectos/projects/cpp/vibecoding/fisica/phys` — user's Box2D-style port: collide.cpp (circle/polygon SAT), manifold, dynamic_tree/broad_phase, distance, block_allocator. Port collision routines from here.
- Box2D-Lite architecture: Body, Arbiter (contact pair), sequential impulse solver with accumulated impulses + Baumgarte bias, Joint base. Arbiters keyed by body-pair id in a map — use `ct::HashMap<uint64 pairKey, Arbiter>`.
- Mouse joint = Box2D b2MouseJoint (soft constraint, target point).
